## 6. Waiting on UmunotaPay

- **What we know:** status endpoint `GET https://api.umunotapay.com/api/v1/payments/{reference}/status`, signed like the collect call (empty body for GET, 5-minute timestamp window). UmunotaPay says `success` for a finished payment. References look like `UMP-` + 12 characters.
- **What we don't know:** the full list of status words, which reference goes in the URL, how long a payment can stay pending, and how payment webhooks are signed and retried.
- **Until then:** `reconcile-payments` stays deployed but **disabled** (`RECONCILE_ENABLED` unset, no cron job). Recommended settings when ready are in the research doc §5.
- **Production payment data (2026-10-03):** 23 transactions, all the founder's own test payments on the UmunotaPay testing dashboard; all now `success`/`paid` (the 6 that were stuck were fixed by a guarded SQL update).

## 7. Founder decisions made today

- **Payments:** host pays for group orders; merchant-directed payouts (not built yet); BOGO pays `buy_quantity`; late payments are accepted once started in time.
- **Social:** nav Home · Search · Social · Profile · Camera (D1); students message only friends or accepted requests (D2); merchants message students who ordered from them (D3; Claude added "or wrote to them first"); student stories are v2 (D4); admins answer reports within 24 hours (D5).

- **Ordering:** verified students only.
- **Groups:** 24-hour limit; reopen when the order is declined or expires; **friend groups** (repeat co-orders) are a post-launch feature (see `02-development-history.md`).

**Founder decisions (2026-10-04):**
- **No deal limits** (no stock, no per-student quantity). A business that runs out uses **Pause** on the deal.
- **Order spam guard: only "3 waiting orders per student".** No per-10-minute limit unless abuse is seen. No CAPTCHA or device fingerprinting.
- **Groups** can be formed and joined any time; only sending them is blocked outside the deal's hours.
- **Email:** custom SMTP through a dedicated Gmail account (`unipicks.team@gmail.com`) until a domain is bought; then move to Resend or Brevo.

**Sentry setup (founder, in the Sentry dashboard):** org `unipicks`, project `unipicks-web` (React, EU region), error monitoring only (no replay, tracing, logs or metrics). Security & Privacy: Data Scrubber on, default scrubbers on, **Prevent Storing of IP Addresses on**. Alert emails go to `unipicks.team@gmail.com` (tested 2026-10-04). Recommended: Allowed Domains = `unipicks.vercel.app`.

**Found, not fixed yet:** the dashboard re-fetches the same data many times (repeated `notifications`, `get_my_role`, `orders` requests); the Vercel variables `ITE_SUPABASE_URL` / `ITE_SUPABASE_ANON_KEY` are misnamed and unused.
